Agent Output Blocks — current + 6 alternatives

2026-10-04

Seven candidates for the instruction block that governs how this agent's replies are shaped. The first is what is in the two instruction files right now (~/.claude/CLAUDE.md and ~/.omo/agent/AGENTS.md); the six after it are alternative consolidations. Pick one and it replaces both sections in both files.

Current — in use now

Style Guide

  • Caveman mode ultra for all agents and subagents; a skill that sets its own caveman level overrides the global level.
  • Prefer bullets over paragraphs.
  • AI-consumed instruction files (skills, CLAUDE.md, AGENTS.md): caveman-compress. Human-read docs, specs, published artifacts: plain prose.
  • Questions: see Question Boundary. Reply shape: see Reply Format.

Reply Format

  • Prefer bullets. Use headings, tables or sections only when bullets cannot carry the structure.
  • No hard cap on length: print what the task needs, as bullets.
  • Bullet = result + pointer (PR/issue URL, `path:line`). Explain how things work only when asked.
  • Never restate: user answers, subagent reports, running-agent lists, prior turn content.
  • Long artifacts (full reports, logs, drafts): print them in full, and also write to a durable home (issue/PR comment, `.claude/plans/<area>/`) when worth keeping.
  • Progress ping ("user hasn't heard from you"): one line.
  • User asks a question: answer first.

Note: the "Always print the output to the terminal" bullet was removed earlier today; nothing in the current state requires output to be printed.

The six alternatives

A — Minimal

Only the rules that change behaviour; four lines.

  • Bullets over paragraphs.
  • Lead with the result.
  • Pointer after each claim (`path:line`, URL).
  • Answer questions first; progress ping is one line.

Differs from current: Drops caveman voice, compression policy, restating ban, artifact-home rule, and the reply-shape pointer.

B — Caveman operator

Voice-first, operator tone.

  • Caveman-ultra voice; a skill may override its level.
  • Fragments. Result first. No preamble.
  • Bullet = result + pointer.
  • Code, paths and error strings verbatim.
  • Progress ping: one line.

Differs from current: Keeps caveman-ultra, drops the compression policy line and the artifact-home rule.

C — Evidence-first

Output must carry its own proof.

  • Result first, evidence directly under it.
  • Every claim carries a pointer or the raw output it came from.
  • Print command output, listings and file contents when they are the evidence.
  • No claim without a source checked this session.
  • Verbatim error text, never paraphrased.
  • Progress ping: one line.

Differs from current: Turns the print-output demand into the block's core rule; drops caveman voice and the restating ban.

D — Ultra-compressed

Payload only.

  • Payload only: all substance kept, fluff cut.
  • One fact once.
  • Fragments where order survives; full sentence where two readings exist.
  • Never cut: code, paths, names, numbers, negations.

Differs from current: Replaces both sections with compression rules; no pointer, artifact or ping rules.

E — Structured report

Fixed shape per reply.

  • Shape: Verdict → Evidence → Next.
  • Evidence bullets carry their artifact path.
  • Long artifacts print in full.
  • Progress ping: one line.

Differs from current: Adds a mandated reply shape; drops bullets-over-paragraphs and caveman voice.

F — Preservation-first

Nothing gets summarized away.

  • Print deliverables in full; a file copy supplements, never replaces.
  • Command output pasted verbatim, not summarized.
  • Errors quoted exactly, with the failing command.
  • No silent truncation: say what was dropped.
  • Progress ping: one line.

Differs from current: Focused on losing no data; drops caveman voice, pointer rule and restatement ban.
